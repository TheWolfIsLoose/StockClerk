# Stock Clerk v0.7 — GUI Overhaul Spec

**Status:** design-locked 2026-09-18, prototype-in-progress
**Scope:** major GUI redesign; no changes to auction/purchase logic
**Companion:** `Dev/NOTES.md` §3.4a carries the decision history and revisit
triggers behind each item here.

---

## Goal

Compress and unify Stock Clerk's on-screen surface. Ship a smaller, sleeker
main window that docks to the Auction House when open and floats when not;
merge the current Settings dropdown and standalone Log window into one
right-attached sidecar panel. Two-tier the activity data so the sidecar shows
only user-meaningful outcomes while `/clerk log` gives a verbose in-game copy
of everything for diagnostics.

## Non-goals (v0.7)

- Any change to auction scanning, purchase queue, cap logic, or budget math
- Sidecar resize handle (deferred to v0.8+)
- Time-horizon selector for activity feed (deferred)
- Overflow handling for small-screen users where dock would clip
- New settings beyond what SettingsDropdown already has
- Any change to `/clerk` or `/clerk log` semantics beyond redirection

---

## 1. Main Frame

### 1.1 Size and shape

- **Default size:** 420 × 400 (down from 680 × 500). Shopping-list feel,
  taller than wide.
- **Resize grip:** keep the existing bottom-right grip.
- **Minimum size:** hard floor at 420 × 400. `SetResizeBounds(420, 400)`.
  User can grow, never shrink below default.
- **Maximum size:** none.
- **Position persistence:** per-character `char.ui.floatPos = { x, y }`.
  Separate from docked position (see §4).

### 1.2 Header

Single line, from left to right:

```
Stock Clerk  v0.7.0                        [☰] [X]
```

- **Title text:** `Stock Clerk` in existing header font/color
- **Version string:** two spaces after title, smaller font, muted gray
  (`|cff888888` or similar). Read via
  `C_AddOns.GetAddOnMetadata("StockClerk", "Version")`; auto-updates on
  every version bump. Falls back to empty string if metadata missing.
- **Sidecar toggle** (`☰`): single hamburger button, ~24×22, top-right
  corner. Replaces the current cog + log button pair entirely.
- **Close X:** enlarged from 28×22 to ~36×28. Tuned in prototype.
- **Row layout:** title left-anchored, buttons right-anchored, both
  vertically centered on the same header baseline.

### 1.3 Toolbar row (below header)

Unchanged from v0.6 except for the filter chip:

- **Add item box + Add button:** unchanged
- **Filter chip:** becomes **icon-only** — a small filter glyph (~20×20)
  in place of the current text chip. Same click behavior (toggles
  `char.ui.stuckOnly`), same persistence. Tooltip on hover:
  `Show only: stuck above cap` / `Show all items` depending on state.

### 1.4 Rows

Row layout and column set unchanged. Single change:

- **Trash icon visibility:** hidden by default per row, shown on hover
  (row `OnEnter` → trash `:Show()`, row `OnLeave` → trash `:Hide()`).
  Trash occupies its usual slot but doesn't visually load the row.

### 1.5 What's removed

- **Cog button** — replaced by sidecar toggle
- **Log button** — replaced by sidecar toggle
- **Text filter chip** — replaced by icon filter

## 2. Sidecar (merged panel)

### 2.1 Attachment

- **Anchor:** TOPLEFT of sidecar to TOPRIGHT of main frame, 0px gap
  (visually reads as one continuous panel, distinguished only by the
  divider at §2.3).
- **Height:** matches main frame height exactly. When main resizes,
  sidecar tracks.
- **Width:** fixed at **260** for v0.7 (matches current SettingsDropdown
  width; fits activity entries without wrapping).
- **Toggle:** hamburger button in main header. Open/closed state
  persisted per-character (`char.ui.sidecarOpen`).
- **Visibility:** hidden when main frame is hidden. Toggle button only
  functional when main is shown.

### 2.2 Layout

Two sections, stacked top-to-bottom:

```
┌────────────────────────┐
│  Settings              │  ← fixed height, always visible
│  ☐ Auto-purchase       │
│  Cap default: [___]    │
│  Daily budget: [___]   │
│  ☐ Open at AH          │
├────────────────────────┤  ← 1px hairline divider
│  Activity              │  ← growable, fills remaining height
│  [10:23] Bought 20× …  │
│  [10:21] Skipped Silk…│
│  [10:18] Cap Silk: …   │
│  …                     │
└────────────────────────┘
```

### 2.3 Divider

- 1px horizontal line spanning sidecar's inner width
- Color matches existing style guide separator (`Palette.border` or
  equivalent)
- Small "Activity" label immediately below divider (left-aligned,
  muted gray, same weight as the header version string)
- Small "Settings" label at top of settings section (matching style)

### 2.4 Settings section (top)

- **Position:** anchored to sidecar top, fixed height (~200px, tuned in
  prototype based on control stack)
- **Content:** current SettingsDropdown controls verbatim:
  - Auto-purchase checkbox
  - Cap default input
  - Daily budget input
  - Auto-open-at-AH checkbox
- **Reason for top-anchor:** rare-use controls must not get buried
  when the sidecar grows (future resize handle). Growable region is
  activity, not settings.

### 2.5 Activity section (bottom)

- **Position:** anchored below divider, fills remaining sidecar height
- **Contents:** see §3
- **Behavior:** pixel-bounded (no fixed count); oldest entries fall
  off as new ones arrive if space is exceeded

## 3. Activity — two-tier data model

### 3.1 Underlying log (unchanged)

The comprehensive event stream currently written to
`StockClerkDB.chars[char].log` continues as-is. Every internal event
still gets recorded. This is the source of truth for both views below.

**No schema changes to underlying log for v0.7.**

### 3.2 Sidecar feed view (new)

Opinionated filter over the underlying log. **Only user-meaningful
outcomes appear here.**

**Include:**
- Manual purchases (successful buys)
- Auto-purchase results (successful buys initiated by auto)
- Cap changes (row-level and default), debounced (see §3.4)
- Auto-purchase blocks with reason (e.g. "over cap", "mail pending",
  "budget exhausted")

**Exclude:**
- Mail arrivals (addon didn't cause them)
- Session start/end markers
- Config changes other than cap
- Refresh cycles, tick events, internal state transitions
- Any external-world event the addon merely observed

**Bounding:** pixel-bounded. Feed renders as many entries as fit in
the activity section's available height. Older entries drop off the
top when new ones arrive.

**Scope:** current game session only for v0.7. Older entries live in
underlying log but aren't shown in the sidecar. Time-horizon selector
deferred.

### 3.3 Entry format

Single line, action-first, absolute HH:MM timestamp:

- **Purchase:** `[HH:MM] Bought 20× Silk Cloth — 15g 30s`
- **Auto-block:** `[HH:MM] Skipped Silk Cloth — price 1g 80s exceeds your cap 1g 50s`
- **Cap change (row):** `[HH:MM] Silk Cloth cap: 1g 50s → 1g 80s`
- **Cap change (default):** `[HH:MM] Default cap: 1g → 2g`

Fields:
- `[HH:MM]` absolute time, muted gray
- Verb (Bought, Skipped, capped-item name) in default text color
- Numbers use existing money formatting (gold/silver/copper)
- Truncate long item names with ellipsis at sidecar width

### 3.4 Cap-change debounce

- Rapid edits to the same cap coalesce
- Log the final value only after **10 seconds of stability**
- Implementation: `C_Timer.After(10, ...)` per-item, canceled and
  restarted on each edit; fires the log entry with the value at
  fire-time
- Prevents feed spam while user is dialing in a price
- Same debounce applies to default cap

## 4. Auction House docking

### 4.1 Trigger events

- `AUCTION_HOUSE_SHOW` → if Stock Clerk is open, snap to dock
- `AUCTION_HOUSE_CLOSED` → if Stock Clerk is docked, snap back to
  remembered float position

### 4.2 Dock position

- Anchor: `SC:SetPoint("TOPLEFT", AuctionHouseFrame, "TOPRIGHT", 1, 0)`
- 1px gap between AH's right edge and Stock Clerk's left edge
- Sidecar (if open) continues right from Stock Clerk normally

### 4.3 Float position

- Persisted per-character in `char.ui.floatPos = { x, y }`
- Stored using `GetPoint()` at drag-stop when not docked
- Restored via `SetPoint("TOPLEFT", UIParent, "BOTTOMLEFT", x, y)` on
  AH-close or on open when AH isn't shown

### 4.4 Setting interaction

- `autoOpenAtAH` (existing setting) governs **opening only**
  - ON: Stock Clerk opens automatically when AH shows (already ships)
  - OFF: Stock Clerk stays closed when AH shows (already ships)
- **Docking is independent.** If Stock Clerk is open at AH-show, it
  docks regardless of `autoOpenAtAH`. Different concerns: one is
  visibility, the other is placement.

### 4.5 Deferred

- Small-screen overflow (dock pushes sidecar off-screen) — user is on
  4K, not solving until a low-res tester reports it
- Left-side docking / user-configurable dock side — no signal yet

## 5. `/clerk log` popup (new)

### 5.1 Purpose

In-game verbose log viewer for diagnosis and sharing with the
developer. Replaces the LogFrame window with a copy-paste-optimized
popup.

### 5.2 Trigger

`/clerk log` slash command. Opens the popup. If already open,
re-opening refreshes contents.

### 5.3 Shape

Minimal custom frame:
- ~500 × 400
- Scrollable multi-line editbox filling most of the frame
- Small title bar with close X
- No copy button, no chrome buttons

### 5.4 Contents

Verbose dump of the underlying log (see §3.1):
- Both user outcomes AND developer/internal addon actions
- Chronological, newest at bottom (natural reading order)
- Each entry timestamped with absolute date+time
- Format: plain text, one event per line, wrapping allowed
- Include event category tags in brackets so entries are greppable
  (e.g. `[BUY]`, `[AUTO-BLOCK]`, `[CAP]`, `[REFRESH]`, `[SCAN]`)

### 5.5 Copy behavior

- On `OnShow`, editbox is **focused and all text selected**
- User's next keystroke (Ctrl-C on Windows, Cmd-C on Mac) copies
- User closes with Esc or clicks the X
- Explicitly does NOT print to default chat frame

### 5.6 LogFrame retirement

- `UI/LogFrame.lua` is retired in v0.7
- Any references from Core/MainFrame/slash-command dispatcher redirect
  to the new popup
- Saved-vars log data unaffected (same underlying storage)

## 7. Persistence changes

New saved-var fields (per-character `char.ui`):

- `char.ui.sidecarOpen` (bool, default false)
- `char.ui.floatPos = { x, y }` (nilable, updates on drag)

Existing fields preserved:
- `char.ui.stuckOnly` (v0.6 filter chip state)
- `char.ui.hidden` / `char.ui.pos` / etc. as currently used

Removed:
- Any `char.ui.settingsDropdownOpen` state (dropdown is gone)
- Any `char.ui.logFrameOpen` / `char.ui.logFramePos` state
  (LogFrame is retired)

## 9. Testing checklist (populated at implementation)

To be filled out as we build. Baseline requirements:

- Main frame resizes down to 420×400 minimum, no smaller
- Sidecar toggles from hamburger; state persists across `/reload`
- Sidecar Settings section controls behave identically to old dropdown
- Sidecar Activity section shows correct filtered entries
- Cap change debounce fires exactly once after 10s of stability
- `/clerk log` opens popup with editbox selected + focused
- AH open snaps main to dock; AH close snaps back to float
- Float position persists per character across sessions
- `autoOpenAtAH` off + AH open → SC stays closed
- `autoOpenAtAH` off + user opens SC + AH open → SC docks anyway
- Version string in header matches TOC after version bump
- Close X visibly larger, hit-testable at new size
- Filter icon toggles same state as v0.6 text chip
- Trash icon appears on row hover, hides on leave
- No regressions to purchase / cap / auto logic
