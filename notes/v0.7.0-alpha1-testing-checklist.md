# Stock Clerk v0.7.0-alpha1 — Feature testing checklist

Retail Midnight 12.1 (interface `120100`). Run through this in a real
game session, ideally on more than one character. Tick the boxes that
pass and jot a one-line note for anything that fails or feels off.

If v0.6.1 shipped after you installed alpha1, update to the next alpha
first so you're testing the keyboard-capture fixes and the alpha
together — otherwise any keyboard-eating symptoms belong to alpha1's
pre-hotfix state, not v0.7 itself.

## 0. First launch sanity

- [ ] `/clerk` opens the redesigned main window (compact ~420×400, not
      the old 680×500).
- [ ] Header shows a version string with amber pre-release color tag.
- [ ] No red Lua errors from `/console scriptErrors 1` on first open,
      first close, and second open.
- [ ] Existing saved list from v0.6.x survives the upgrade (items,
      targets, caps all still present).

## 1. Compact main window

### Frame sizing

- [ ] Frame opens at ~420×400 by default.
- [ ] List area auto-sizes to number of items (small list = short
      frame, not a big empty rectangle).
- [ ] Drag bottom-right corner to resize larger — resize works, list
      grows to fill.
- [ ] Drag corner to resize smaller — min-size clamp still holds
      (frame doesn't collapse to nothing).
- [ ] Resized dimensions persist across `/reload`.
- [ ] Frame position persists across `/reload`.

### Row layout

- [ ] Item column keeps room for long names (test with something like
      "Elemental Potion of Ultimate Power" or a long enchanting
      material name).
- [ ] Need, Cap, Seen columns compress to their content width.
- [ ] Header row aligns with body row columns.

### Have column state colors

- [ ] Row with `Have < Need` shows Have in red.
- [ ] Row with `Have >= Need` shows Have in mint green.
- [ ] Crossing the threshold live (buy something, mail something in,
      dust off a stack) recolors the row without needing a `/reload`.
- [ ] Status pill from v0.6 is gone (no leftover widget in the row).

### Filter chip

- [ ] Filter chip is the 3-bar funnel icon in the column-header strip
      (icon-only, no text label).
- [ ] Clicking it toggles the "over-cap only" filter.
- [ ] Toggled state is visually obvious (highlighted/pressed vs idle).
- [ ] Filter behavior matches v0.6: only rows currently priced above
      cap are shown when active.
- [ ] Toggle survives `/reload`.

### Header buttons

- [ ] Close X is visibly larger than v0.6, easy to click.
- [ ] Hamburger button is present next to the X.
- [ ] Hamburger button opens/closes the Sidecar (see section 2).
- [ ] Tooltips on X and hamburger read cleanly.

### Version tag

- [ ] Amber-colored version string reads `0.7.0-alpha1` (or the
      current alpha number).
- [ ] On a Stable-channel install (v0.6.1) the tag isn't amber — it's
      the normal color. (Sanity check that pre-release tinting only
      applies to pre-releases.)

## 2. Sidecar (Settings + Recent Activity)

### Opening / closing

- [ ] Hamburger button toggles the Sidecar (right-docked panel).
- [ ] Sidecar docks flush to the right edge of the main window.
- [ ] Sidecar follows the main window if you drag it.
- [ ] Closing the Sidecar returns the main window to its natural
      width (no leftover padding).
- [ ] Sidecar open/closed state persists across `/reload` per character
      (character A opens it, /reload, still open; character B has its
      own independent state).

### Settings section (top half)

- [ ] Auto-purchase toggle reflects and updates the same setting the
      v0.6 dropdown showed.
- [ ] Default cap field accepts gold input and saves on Enter / focus
      loss.
- [ ] Auto budget per day field accepts input and saves.
- [ ] Auto-open at AH toggle reflects and updates the setting.
- [ ] Every setting round-trips: change it, `/reload`, still set.
- [ ] Every setting matches what `/clerk settings` (or the previous
      dropdown, if still accessible) reports.

### Recent Activity section (bottom half)

- [ ] Recent Activity shows the last ~30 log entries.
- [ ] A fresh action (add an item, change a cap, trigger auto-block)
      appears in the feed within a second, without needing a manual
      refresh.
- [ ] Purchase entries are tagged `[BUY]`.
- [ ] Cap changes are tagged `[CAP]`.
- [ ] Auto-block reasons are tagged `[AUTO-BLOCK]`.
- [ ] Cap-change debounce works: type in a cap field, backspace a
      digit, retype it, blur. Feed shows ONE `[CAP]` entry, not
      several.
- [ ] Feed scrolls if entries exceed visible rows.
- [ ] `[KBD]` entries render in red if the watchdog fires (won't
      normally trigger; if v0.6.1 fixes hold, this section stays
      empty of `[KBD]` lines).

### Interactions

- [ ] Opening/closing Sidecar mid-purchase-loop doesn't interrupt
      the loop.
- [ ] Sidecar's Recent Activity keeps updating while a purchase loop
      is running.

## 3. `/clerk log` popup

- [ ] Typing `/clerk log` opens a ~500×400 popup, separate from the
      main window.
- [ ] Popup is movable via title-bar drag.
- [ ] Log text is pre-selected on open — Ctrl+C copies immediately
      without needing a manual select-all first.
- [ ] Pasting the copied text into Discord / a bug tracker preserves
      linebreaks and readable spacing.
- [ ] Every entry line has a bracketed tag: `[BUY]`, `[BUY-FAIL]`,
      `[BUY-SKIP]`, `[BUY-TRY]`, `[CAP]`, `[TARGET]`, `[ADD]`,
      `[REMOVE]`, `[SEARCH]`, `[LOOP-START]`, `[LOOP-STOP]`, `[AUTO]`,
      `[AUTO-BLOCK]`, `[STATUS]`, `[KBD]`.
- [ ] Clear Log button in the popup empties the log after confirm.
- [ ] Popup can be closed with Escape / X and reopened cleanly.
- [ ] Opening the popup while the Sidecar is open doesn't scramble
      either panel's layout.
- [ ] Log capacity respected: after 500+ entries, oldest ones fall
      off (don't crash, don't lag).

## 4. Auction House docking

Auto-open at AH must be ON for this section.

- [ ] Open the Auction House. Stock Clerk main window appears docked
      to the AH's right edge.
- [ ] The two windows sit side-by-side — no overlap.
- [ ] Docking respects screen edge: if the AH is near the right edge
      of the screen, Stock Clerk doesn't clip offscreen. (May need
      manual repro on ultrawide + non-ultrawide.)
- [ ] Close the Auction House. Stock Clerk restores to its last
      floating position (the position it was in before you opened
      the AH).
- [ ] Drag Stock Clerk somewhere new WHILE the AH is open. Close AH.
      Stock Clerk restores to the pre-docking floating position, NOT
      the docked-and-dragged position. (Docked coords are transient.)
- [ ] `/reload` while docked, then close AH — restores correctly.
- [ ] With Sidecar OPEN before opening AH: dock happens, Sidecar
      follows to the new anchor and stays open.
- [ ] With Sidecar CLOSED before opening AH: dock happens, Sidecar
      stays closed.
- [ ] Auto-open at AH set to OFF — opening AH does NOT dock, main
      window doesn't auto-appear.

## 5. Regression: v0.6.x behavior still works

Feature areas that shipped in v0.6 and must continue to work under the
v0.7 redesign.

### Quick-add gestures (from v0.6.0)

- [ ] Drag an item from bags onto the Add box → itemID appears.
- [ ] Shift-click Add box while holding item on cursor → itemID
      appears.
- [ ] With Add box focused, shift-click an item link in chat / tooltip
      / AH → itemID routes into Add box (not into chat).
- [ ] Press Enter with a valid itemID in Add box → item is added to
      the list.

### Inline row editing

- [ ] Click the Need cell on a row → inline editor opens.
- [ ] Type a number, press Enter → new Need value saves, row updates.
- [ ] Click the Price Cap cell on a row → inline editor opens.
- [ ] Type gold amount, press Enter → new cap saves.
- [ ] Escape while editing cancels without saving.
- [ ] Tab from Add box → Count box → Price box → Add button → first
      row cell (soft-select) still works end-to-end.

### Keyboard capture (v0.6.1 hotfix regression)

This is the acute bug v0.6.1 fixed. If any of these fail on alpha1,
that's a merge or backport miss.

- [ ] Open an inline Need editor with focus. Trigger a bag update
      (loot something, move a stack, use a consumable). Keyboard is
      NOT eaten — chat, movement, hotbars still work.
- [ ] Open an inline editor. Toggle the filter chip. Keyboard NOT
      eaten.
- [ ] Open an inline editor. Scroll the list. Keyboard NOT eaten.
- [ ] Focus the Add button (Tab into it). Trigger any error path
      (add a garbage itemID, cancel with Escape). Keyboard NOT eaten.
- [ ] Close the main window while an editor is focused. Reopen.
      Keyboard NOT eaten; no orphan focus ring.
- [ ] Press Escape repeatedly to close/reopen the window a bunch.
      Steady state after: keyboard works normally in game.

### Purchase loop

- [ ] Manual `/clerk buy` with items over target still fires the buy
      loop.
- [ ] Loop start / stop entries appear in `/clerk log`.
- [ ] Auto-purchase toggle (from Sidecar Settings) starts / stops
      correctly.
- [ ] Auto budget per day is honored (once the day's budget is spent,
      further purchases refuse with `[AUTO-BLOCK]`).

## 6. Multi-character

- [ ] Character A and character B keep independent character-scoped
      state (list, per-char settings) but share global state (log,
      defaults).
- [ ] Log entries from character A show up when viewed on character B
      with a "· on <A>" suffix.
- [ ] Sidecar open/closed state is per-character (A open ≠ B open).

## 7. Reload / relog stress

- [ ] Open main window, open Sidecar, `/reload` → both restore.
- [ ] Open `/clerk log` popup, `/reload` → popup closes cleanly (it's
      transient), no error on next `/clerk log`.
- [ ] Full logout to character select, log back in → saved list, saved
      settings, saved sidecar state all restore.
- [ ] Alt-tab out mid-purchase-loop and back in → loop still running
      (or stopped cleanly if the AH closed).

## 8. Known alpha caveats — confirm, don't file as bugs

- [ ] Sidecar and `/clerk log` popup strings are English-only. Not a
      bug on this alpha.
- [ ] `UI/LogFrame.lua` is still shipped as a compat shim. Fine on
      alpha; slated for full removal in v0.8. If you see stale
      references to it, note them but don't block on them.

## What to report back

For each item that fails or feels off, note:

1. Which section / checkbox.
2. Repro steps (as terse as possible).
3. Whether `/clerk log` shows any `[KBD]` entries at the time.
4. Any red Lua errors (from `/console scriptErrors 1` — copy the
   text).

For each item that PASSES cleanly, no need to write anything — the
absence of a note is the pass signal.
